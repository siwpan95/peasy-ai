## 4. 过程中的关键修正：必须用**条件**模型打分

最初直接拿 P2 训好的**无条件**语言模型去算 P(回答|问题)，结果 top-1 只有 5%。

| 打分模型 | top-1 | MRR |
|---|---|---|
| 无条件 LM（训练时 context 只有回答内部前驱） | 5.00% | 0.3161 |
| **条件 LM**（训练序列 `[BOS] 问题 SEP 回答 EOS`） | **40.00%** | 0.6121 |

根因是**训练与推理的 context 分布不一致**：推理时把问题当条件前缀拼在前面，训练时却从未见过这种拼接。这不是调参问题，是方法学错误 —— 要用 P(回答|问题) 打分，训练就必须带条件（`fit(conditions=...)`）。修正后 top-1 提升 8 倍（5% → 40%）。

## 5. 诚实结论

- 即便修正为条件模型，CNN 打分（40%）**仍不如朴素的字符 bigram Jaccard（60%）**。
- 原因不难理解：7950 token 的小语料 + window=4，卷积学不到足够的语义匹配能力；而这条语料里问题与答案共享大量实词（「镜子」↔「镜面」），朴素词汇重叠反而直接有效。
- 样本量仅 20 条留出对，60% vs 40% 相当于 12 条 vs 8 条，**差异不足以定论**。
- 因此打分器做成可配置：`scorer: cnn | jaccard | hybrid`，让实测数据决定用哪个，而不是把某个方案写死。

这个任务之所以值得单独立一项：它衡量的是 **teacher-forcing 的排序质量**，正是 P2 证明 TextCNN 强于 n-gram 的场景（留出集 top-1 +9.14pp）；而自由生成会让 CNN 输给记忆型的马尔科夫。把模型放在它被证明擅长的场景里，才是这次改造的意义 —— **但「擅长的场景」不等于「一定能赢」，实测仍然可能输给更朴素的方法。**
